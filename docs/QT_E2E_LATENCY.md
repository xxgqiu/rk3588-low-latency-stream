# Qt 客户端与拍照法端到端延迟

## 客户端职责

`qt_rtsp_client` 使用 FFmpeg 完成 RTSP demux、H.264 解码和 RGB 转换，Qt
负责显示。解码在后台线程运行，GUI 线程通过容量为 1 的 latest-frame mailbox
取得最新画面；GUI 变慢时覆盖旧帧，而不是让显示延迟持续累积。

客户端显示：

- 解码输出 FPS；
- 接收码率；
- 平均/最大解码耗时；
- 累计包、帧、错误；
- GUI 未及时显示而被覆盖的旧帧数。

这些是客户端内部指标，不等于摄像头到屏幕的光学端到端延迟。

## 拍照法

1. 手机打开毫秒级单调计时器；
2. 摄像头对准手机计时器；
3. Qt 客户端显示经过 Camera → RGA → MPP → RTSP → Decode 的手机画面；
4. 用第三台设备拍下“真实手机计时器”和“电脑上的回传计时器”同框照片；
5. 对照片读取两个数值：

```text
端到端延迟 = 拍照瞬间的真实计时器 - 回传画面中的旧计时器
```

建议至少采集 30 张有效照片，报告中位数与 P95，不只挑选最好的一张。手机屏幕
刷新、相机曝光、显示器刷新和照片读数都会引入量化误差，因此结果应写成实测分布，
不能宣称 1 ms 精度。

## 构建与运行

```bash
./scripts/build_qt_client.sh
./scripts/run_qt_client.sh rtsp://<BOARD_IP>:8554/live/main
```

当前仓库提供工具和方法，但尚未提交 30 组正式样本，所以性能报告不虚构
glass-to-glass 中位数或 P95。
